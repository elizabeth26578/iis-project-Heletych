Лабораторна робота №4

Продукційна база знань у CLIPS

Предметна область: Діагностика несправностей автомобіля  

Мета роботи

Реалізувати концептуальну модель предметної області
«Діагностика несправностей автомобіля» як продукційну
базу знань у CLIPS.

Навчитися описувати факти за допомогою `deftemplate`,
створювати продукційні правила, використовувати змінні,
обмеження, заперечені умови та `salience`, а також
перевіряти базу знань на дефекти.

Вихідний масив знань

Основою бази знань є результати лабораторної роботи №2.

Було використано:

-факти F1–F7;
-правила R1–R15;
-винятки E1–E3;
-метазнання M1–M3;
-обмеження L1–L2;
-зафіксовані прогалини G1–G7.

Основний принцип системи: DTC не розглядається як
однозначний діагноз конкретної деталі.

DTC використовується як діагностична ознака для
визначення ймовірної зони несправності, після чого
результат уточнюється за симптомами, параметрами
та додатковими перевірками.


2.Шаблони

У базі створено 8 шаблонів:

1.`автомобіль` — опис автомобіля;
2.`obd_стан` — стан підключення OBD;
3.`dtc` — діагностичний код несправності;
4.`параметр` — поточний параметр автомобіля;
5.`симптом` — діагностична ознака;
6.`гіпотеза` — ймовірна зона несправності;
7.`рекомендація` — наступна діагностична дія;
8.`попередження` — обмеження або виняток.

Приклад:

```clips
(deftemplate dtc
   (slot авто (type SYMBOL))
   (slot код (type SYMBOL))
   (slot перша_позиція
      (type SYMBOL)
      (allowed-values P B C U невідомо))
   (slot друга_позиція
      (type INTEGER)
      (allowed-values 0 1 2 3 -1))
   (slot тип
      (type SYMBOL)
      (allowed-values generic manufacturer reserve невідомо))
   (slot система (type SYMBOL)))

Приклад 1. Визначення системи за DTC
(defrule R2-система-P
   (declare (salience 10))
   ?d <- (dtc
      (перша_позиція P)
      (система невідомо))
   =>
   (modify ?d
      (система двигун-або-акпп)))

Приклад 2. Generic-код
(defrule R6-загальний-код
   (declare (salience 10))
   ?d <- (dtc
      (друга_позиція 0)
      (тип невідомо))
   =>
   (modify ?d (тип generic)))

Приклад 3. Код виробника
(defrule R7-код-виробника-1
   (declare (salience 10))
   ?d <- (dtc
      (друга_позиція 1)
      (тип невідомо))
   =>
   (modify ?d (тип manufacturer)))

Приклад 4. Формування ймовірної зони
(defrule R1-dtc-визначає-зону
   (dtc
      (авто ?a)
      (система ?s&~невідомо))
   =>
   (assert
      (гіпотеза
         (авто ?a)
         (зона ?s)
         (підстава dtc)
         (впевненість 0.6))))

Приклад 5. Врахування виробника
(defrule R9-врахувати-виробника
   (dtc
      (авто ?a)
      (тип manufacturer))
   (автомобіль
      (id ?a)
      (виробник ?m&~невідомий))
   =>
   (assert
      (рекомендація
         (авто ?a)
         (дія використати-таблицю-кодів-виробника)
         (пріоритет високий))))

Приклад 6. Використання поточних параметрів
(defrule R13-відхилення-як-ознака
   (параметр
      (авто ?a)
      (назва ?n)
      (стан відхилення))
   =>
   (assert
      (симптом
         (авто ?a)
         (назва ?n)
         (джерело параметр))))

Приклад 7. Виняток E1
(defrule E1-dtc-не-остаточний-діагноз
   (dtc (авто ?a))
   (not
      (попередження
         (авто ?a)
         (текст dtc-не-є-остаточним-діагнозом)))
   =>
   (assert
      (попередження
         (авто ?a)
         (текст dtc-не-є-остаточним-діагнозом))))

Приклад 8. Діагностика без DTC
(defrule G3-без-dtc
   (obd_стан
      (авто ?a)
      (є_dtc ні))
   (симптом
      (авто ?a)
      (назва ?s))
   =>
   (assert
      (гіпотеза
         (авто ?a)
         (зона потребує-уточнення)
         (підстава симптом)
         (впевненість 0.4))))
